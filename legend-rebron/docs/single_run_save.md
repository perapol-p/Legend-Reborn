# Single-slot Normal run save
Normal pause menu: Save and Go Back to Main Menu, plus Save and Quit to Desktop. Continue appears directly beneath Play when a valid active save exists and shows stage/character/level/time. A new Normal run immediately replaces the single slot; selecting a stage without starting gameplay does not replace it. Practice never overwrites or clears it. Normal Victory and Game Over clear the slot; Retry starts and saves a fresh run.
GameData.active_run_path defaults to user://active_run.save. FileAccess stores versioned Variant data without object deserialization; writes use a temporary file and rename to replace the checkpoint. Failed saves show an error in the pause menu and prevent leaving, retaining the earlier save. Character unlocks/settings remain in their own existing files.
run_save_codec.gd captures character, stage, level/XP, owned item stacks, weapon levels, HP damage, active time/regeneration, kills, reward offers/queue/pity and RNG; player pose/movement; ammo/reloads/cooldowns/queued attacks and weapon animation; combo; spawn counters/time/RNG; all living enemies including boss HP/age/pressure/windup; player/enemy projectiles, shared bow-volley history, tornadoes, charge targets and music playback position. Old physics RIDs are mapped to saved enemy indices and rebuilt on load. Held mouse attacks reset rather than auto-firing on Continue.
Validation scripts: verify_single_run_save.gd (real menu flow, latest-stage overwrite, Practice isolation, boss HP and victory), verify_run_save_runtime.gd (pending item choices/RNG and in-flight effects, Game Over), verify_save_writer.gd + verify_save_reader.gd (disk persistence across separate processes). Test save paths are separate from the user's slot. Screenshots: save_pause_menu.png and save_continue_menu.png. Existing renderer/audio shutdown warnings in test runs remain as previously documented.
